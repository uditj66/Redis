How It Works

Your browser talks to an Express + Upstash Redis backend. Here's the flow.

🗄️

Bit Array in Redis

A single Redis key holds 2048 bits (256 bytes). Tiny — even with 1000 registered users.

#️⃣

4 Hash Functions

Each username passes through 4 djb2-variant hashes, each mapping to a position in [0, 2047].

⬆️

Register → SETBIT

Redis sets SETBIT bloom:usernames pos 1 for all 4 positions, and saves the name in a sorted set.

🔍

Check → GETBIT

GETBIT × 4 in a pipeline. Any bit = 0 → definitely free. All 1s → check confirmed set for ground truth.

🧠 False Positives vs False Negatives

False Negative: Bloom Filters have zero false negatives. If any bit is 0, the username is definitively available — no exceptions.

False Positive: When hash collisions cause all 4 bits to be set by other usernames, the filter may say "possibly taken" for a free name. This app cross-checks the Redis sorted set to tell you if it's a real collision or a false positive.

With m=2048, k=4, and n users: FP rate ≈ (1 − e−kn/m)k. Add more usernames and watch it climb!
